# Repository organization audit — 2026-09-03

Baseline: `origin/main` at `6b3e16aed489507cc9140c0dacb677785792da7d`.
This is a follow-up to
[`CI_RELEASE_PROCESS_AUDIT_2026-09-02.md`](CI_RELEASE_PROCESS_AUDIT_2026-09-02.md).

## Scope and method

The audit classified all **2,242 tracked files** by their nearest package
manifest, Moon project, release carrier, generated-data owner, or repository
role. It also inspected:

- all 52 Moon project roots and every Cargo, pnpm, SwiftPM, and Gradle manifest;
- every root-level file and every top-level/second-level directory;
- exact-content hashes, zero-byte files, largest files, generated markers,
  single-file leaf directories, and repeated basenames;
- callers of suspicious root tools, copied headers, shared query cores,
  product-local scripts, and generated catalogs; and
- open PR #166, which already replaces the three copied JavaScript query and
  protocol implementations with a private workspace package.

Generated carrier fixtures, vendored patch bytes, legal notices, and lockfiles
were judged by ownership, provenance, and consumers rather than by manually
interpreting each generated byte.

## Verdict

The broad `src/{bindings,docs,extensions,postgres,runtimes,sdks,shared,sources}`
shape is sound. Most apparent duplication exists because published npm, Cargo,
SwiftPM, Maven, and React Native packages must be self-contained. The real
problems were a stale docs asset, one Gradle fixture using Swift-style directory
names, stale tree documentation, misleading task names, and one root tool that
was omitted from affected-CI ownership. Qualification also exposed one release
validator that confused host umask bits with Git-tracked source identity.

Large path-only moves are not justified. They would invalidate imports, release
locks, caches, and historical evidence without deleting code or changing
ownership.

## Boundary judgments

| Boundary | Judgment |
| --- | --- |
| Repository root | Correct: workspace manifests, shared policy/configuration, legal files, and public package-manager entrypoints only. Root `Package.swift` is required for the tagged SwiftPM package and points into the Swift-owned source tree. |
| `src/runtimes` | Correct: runtime binaries, C ABI implementation, platform carriers, and runtime-owned build scripts remain together. `liboliphaunt/{native,wasix,wasix-postmaster}` are distinct runtime products, not directories to flatten. |
| `src/sdks` | Correct after renaming the Kotlin standalone consumer fixture. Rust uses Cargo `src`/`tests`, Swift uses `Sources`/`Tests`, Kotlin uses Gradle/KMP source sets, and TypeScript/React Native use package-local `src` and tests. |
| `src/bindings` | Correct: WASIX Rust and TypeScript are public bindings over the portable runtime, not native SDK implementation directories. Their nested package roots are registry boundaries. |
| `src/extensions` | Correct: source/catalog/model data is separate from native/WASIX artifact-producing projects. Identical native/WASIX target files are explicit carrier declarations, not accidental source copies. |
| `src/shared` | Correct: only contracts and source consumed by multiple products live here. JavaScript and Rust query cores are semantic source boundaries; fixtures are shared only when multiple product-native suites consume them. |
| `src/postgres` and `src/sources` | Correct: product-neutral PostgreSQL/toolchain/source pins are separate from runtime-specific patches and overlays. Similar names represent different ownership, not duplicate files. |
| `src/docs` | Correct Next.js package layout after deleting the unused Docusaurus-style `static` favicon copy. Public assets belong in `public`. |
| `tools/runtime` | Correct at root: its two utilities are consumed by native, WASIX, Rust, Swift, Kotlin, JavaScript, and performance lanes. Moving them into one product would invert ownership. |
| `tools/graph` | Correct as a small cohesive module: affected-file normalization and CI-plan construction are shared by workflow, policy, and release consumers. A path-only rename is not useful. |
| `tools/native-*` | Correct as unpublished cross-product Cargo tools. `native-extension-proof` is a hosted proof executable, `native-tools-proof` is conformance testing, and `native-packaging` assembles SDK/runtime resources across products. |
| `tools/release` | Correct owner but too flat. Its 345 files coordinate multiple registries and products, so moving them under any product would be wrong. A short README now identifies entrypoints and the rule for future splits; mass renaming is deferred until a real independent task/import boundary exists. |
| `.github` | Correct: workflow-only adapters/actions stay here; reusable release policy remains in `tools/release` and workflow security in `tools/policy`. Tests may live with the workflow module or in the policy/release suite that owns the contract. |
| `examples` | Correct: paired native/WASIX examples intentionally remain standalone consumer projects. Their small repeated configs/styles preserve copyability and do not justify a shared package. |
| `docs/internal` | Correct: it is explicitly an archived, non-normative evidence area. Large completed checklists remain useful historical records and are not active policy. |

The Rust root is an idiomatic virtual workspace with one shared lockfile, as
described by the [Cargo workspace documentation](https://doc.rust-lang.org/cargo/reference/workspaces.html).
Swift targets and resources remain target-scoped under standard package roots,
with an explicit root manifest path where the public tag requires it, matching
[SwiftPM target-path rules](https://docs.swift.org/package-manager/PackageDescription/PackageDescription.html).
The docs asset fix follows Next.js's documented
[`public` static-file boundary](https://nextjs.org/docs/pages/api-reference/file-conventions/public-folder).
The Kotlin fixture now follows Gradle's lowercase project-directory convention
instead of imitating SwiftPM's `Tests` layout, consistent with Gradle's
[multi-project organization guidance](https://docs.gradle.org/current/userguide/organizing_gradle_projects.html).

## Duplicate-content judgments

- **Remove via PR #166:** three 2,457-line JavaScript query mirrors, three
  protocol mirrors, duplicate protocol-fixture adapters, and redundant Bun/Deno
  entrypoint wrappers. Reimplementing that open PR here would create conflicts.
- **Keep three SDK C-header copies:** SwiftPM, Maven/AAR, and React Native npm
  consumers require package-local headers after checkout/installation. A
  source-level relative include would escape the published package. The
  `sdk-contracts:headers` task enforces byte identity with the canonical native
  header.
- **Keep per-target AOT and broker crates:** every directory is a separately
  published carrier with its own Cargo identity and payload. Their tiny repeated
  `build.rs`/`lib.rs` files are required registry roots; a shared build
  dependency would add publication ordering for no meaningful code saving.
- **Keep repeated version files and empty changelogs:** these are product-local
  release-manager inputs. The three empty changelogs are valid first-release
  placeholders owned by Release Please.
- **Keep duplicate extension/legal fixtures:** they model exact package/archive
  contents. Deduplicating them would stop the fixture from representing the
  installed carrier.
- **Keep small paired-example duplicates:** Electron/Tauri native and WASIX
  examples are intended to be copied and run independently.
- **Deleted:** `src/docs/static/img/favicon.svg`; the identical
  `src/docs/public/img/favicon.svg` is the only copy consumed and emitted by the
  Next.js application.

## Changes made

1. Renamed `src/sdks/kotlin/Tests/PublicApiConsumer` to
   `src/sdks/kotlin/tests/public-api-consumer` and updated the Gradle formatter
   and package-consumer check. This is a standalone Gradle fixture, not a SwiftPM
   `Tests` tree.
2. Deleted the unused duplicate docs favicon under `static`; retained the
   standard Next.js `public/img/favicon.svg`.
3. Added `tools/native-extension-proof/**/*` to the existing release planner
   trigger and a chaos test. Editing the hosted proof executable now selects the
   native extension lifecycle that actually consumes it.
4. Renamed `native-tools-proof:check` and `native-packaging:test` to truthful
   `unit` tasks. Removed `native-packaging:unit -> check`; `cargo test` already
   compiles the crate, and the separate target directories previously repeated
   that work.
5. Replaced the stale fictional tree in
   `docs/maintainers/repo-structure.md` with the current product hierarchy and
   documented why the root Swift manifest is valid.
6. Added `tools/release/README.md` as the minimal navigation/ownership index for
   the large cross-product release directory.
7. Removed two nonexistent reference-audit commands from the local
   qualification skill. Advisory file-usage investigation remains manual; the
   guide no longer instructs maintainers to run targets Moon cannot resolve.
8. Fixed the broker dependency-license source validator to accept readable,
   non-executable checkout modes such as `0664`. Git records only the executable
   bit for regular files; staged and archived carrier members are still
   normalized and verified as exact `0644`.
9. Deleted `.moon/tasks/exact-extensions.yml` and removed the contrib leaf task.
   The eight projects remain valid source/release identity boundaries, but their
   identical package wrappers had no caller; source changes still select both
   shared artifact builders and `extension-packages:package`.
10. Split policy-owned and release-owned mutation tests into separate Moon
    tasks, left workflow/planner tests with `.github`, and narrowed each task's
    real inputs. This removed a 152-file release-suite launch from policy-only
    edits without moving source away from its owner.
11. Corrected the nested WASIX TypeScript task names, activated the previously
    dead repository format gate, and moved Node Direct/WASIX N-API metadata and
    carrier checks under their truthful `package` tasks.
12. Deleted the one-use `select-affected-moon-targets.mjs` wrapper. The matrix
    writer now filters its already-loaded affected task map, reducing the real
    all-task plan from roughly 20 Moon queries to two without changing output.
    The root static aggregate also stopped pulling `native-tools-proof:unit`,
    which already has a Tests-matrix owner.
13. Removed global release bookkeeping from product behavior/build task inputs.
    A product `release.toml` now invalidates that product's carrier plus release
    graph/metadata proof; the central manifest no longer rebuilds artifacts.
14. Made the macOS publication-host metadata job affected-only and metadata-only.
    It remains mandatory for exhaustive push/manual runs and relevant PRs.
15. Replaced 129 one-file Bun syntax processes with one multi-entry build. The
    same policy syntax surface now completes locally in 1.4 seconds.
16. Removed `.moon/cache` from `release-tools:graph-unit`'s own input set and
    narrowed its release-tool closure. Its 27 tests now cache under a stable key,
    and release helpers no longer schedule it beside the full release suite.
17. Corrected docs task ownership: build no longer reruns the separate static
    check, and read-only smoke no longer declares the consumed build tree as its
    own output. Removed three hidden WASIX TypeScript package-smoke prerequisites
    that hosted CI already executes explicitly before artifact assembly.
18. Aligned the WASIX N-API compile cache directory with the public task name,
    and stopped formatter/syntax-wrapper edits from launching unrelated policy
    mutation tests.

## Deliberately not changed

- [PR #166](https://github.com/f0rr0/oliphaunt/pull/166) owns the JavaScript
  source-sharing conversion, but is not merge-ready. Its WASIX TypeScript build
  cannot resolve `@oliphaunt/js-core/query` or `/protocol`, and its Node Direct
  cleanup fixture cannot resolve the same package while bundling raw SDK
  sources. The ownership model is sound; every raw-source compiler/bundler must
  resolve the private workspace package before the copied files are removed.
- No symlinks were introduced. They are poor registry/Windows package
  boundaries and would make source archives host-dependent.
- No mass rename of underscore-named release scripts was performed. Those paths
  are invoked by workflows and release tooling; naming consistency alone does
  not justify that failure surface.
- `tools/xtask` remains at the root because its surviving commands span WASIX
  source acquisition, runtime assets, extensions, AOT, and release staging.
  Earlier dead commands were removed; moving the remaining crate would only
  move complexity.
- No generated extension, SDK, package-carrier, lockfile, legal, or recorded
  evidence bytes were deleted.
