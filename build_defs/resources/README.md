# Database resource construction

The first slice constructs the pinned ICU data archive and its npm, Cargo and Maven carriers, plus the standard and ICU Linux x64 PostgreSQL seeds and their npm, Cargo and GitHub artifacts. `//src/database-resources:linux_shipping_export` exposes these 12 roots through the existing shipping provider. This is partial coverage of the database-resources product; it does not satisfy complete product admission.

Bootstrap consumes the selected native runtime, actual PostgreSQL configuration headers and the canonical seed contract. The ABI receipt comes from those headers, including resolved integer aliases. The ICU profile additionally consumes the actual pinned data archive. Consumer requirements record the runtime version passed to the packaging action, and the manifests identify the consumed PostgreSQL and initdb binaries.

PostgreSQL bootstrap intentionally consumes clock, PID and random state. A new bootstrap can produce different physical bytes for identical declared source inputs. Release affectedness must use the consumed source inputs and completed publication history; a fresh PGDATA hash cannot select a release. Publication freezes the original admitted archive bytes through the existing candidate mechanism. Validation opens disposable copies, and does not normalize control or WAL contents.

The bootstrap output is a plain tar File containing every required empty directory, the original PGDATA files, its producer manifest and its actual ABI receipt. Bazel TreeArtifacts omit empty directories when transferred between actions, so they cannot be the seed transport. Archive adapters copy declared Bazel file aliases into private regular files before invoking the existing strict archive readers.

`//src/database-resources:linux_resource_test` checks the packed resource bytes, canonical versions and producer hashes, header receipt, ICU profile behavior, SQL persistence across reopen and failure when the extracted runtime library is removed. Its scratch database roots use the SDK's production descriptor publisher. The consumer receives the separate ICU carrier through the runtime API and rejects its removal; bundled runtime data cannot satisfy that test. It also rejects a PostgreSQL error containing the expected result text. Linux construction does not establish the remaining foreign host or mobile ABI domains.

The qualified Linux x64 target and execution profile pass both resource tests. An unchanged warm invocation executes no bootstrap, packaging or consumer actions, and the 19 physical outputs behind the 12 shipping roots retain their SHA-256 and size. This establishes reuse of frozen bytes, rather than reproducibility of a fresh bootstrap.

The Android construction slice also passes locally. `native_target_abi` reads the selected PostgreSQL headers and inspects the compiled runtime for its actual platform; the Android transitions produce separate arm64 and x86_64 receipts. Domain binding compares both receipts with the original Linux bootstrap receipt, checks the canonical Datum64 fields, and preserves PGDATA bytes and empty directories. It reuses the same GitHub, npm, Cargo and Maven writers.

Build `//src/database-resources:android_datum64_standard_carriers` and `:android_datum64_icu_carriers` to construct all 16 final envelope files behind the ten new Android shipping roots. Shipping exports write the construction index; they do not force indexed artifact actions. Independent inspection checks the archive, npm/Cargo/Maven identities, runtime pin and exact original seed bytes. The warm request reruns no bootstrap, receipt, domain-binding or envelope producer, and retains identical SHA-256 and size for all 20 inspected outputs, including the four original/domain frozen tar files.

The WASIX construction slice also passes locally. `//src/database-resources:wasix_resource_test` consumes the actual portable runtime, the standard Cargo seed-runner target with its authored feature, and the separate ICU data archive. Both profiles run the existing WASIX initdb constructor, freeze the authentic PGDATA bytes and preserve its empty directories. The manifests record the exact consumed runtime version and PostgreSQL/initdb module hashes; WASIX retains its distinct Datum32 physical format.

The test checks exact archive/npm/Cargo contents and canonical identities, exercises the SDK's actual resource-parser sources with the pinned fzstd package, and rejects wrong runtime versions, module hashes, physical format, compatibility key, archive bytes and ICU tree hashes. The independent Rust verifier opens private packaged-seed copies with actual PostgreSQL, checks both profile probes, writes rows and reads them in a later process. Missing ICU data and `pg_control` fail. Six Rust unit tests also run through the declared execution configuration, covering error capture, required empty directories and rejection of work directories inside inputs before filesystem mutation.

Build `//src/database-resources:wasix_standard_carriers` and `:wasix_icu_carriers` for the two profiles' final npm/Cargo envelopes and archive/manifest inputs; `:wasix_shipping_export` indexes their eight canonical shipping roots. The unchanged warm request passes in 0.568 seconds with zero executed producers or tests, and all ten inspected carrier/archive/manifest/frozen files retain their SHA-256 and size. This proves reuse of the admitted frozen bytes. The portable PostgreSQL module's export policy consumes actual extension side-module imports, so constructing that exact consumer module also requires their compile closure.

Construction now covers 17 of 33 registry carriers and 13 of 31 GitHub identities. Android execution, eight remaining seed variants, combined Swift packaging and the complete checksum aggregate remain unqualified. The iOS domain requires genuine device, simulator and Mac producer receipts; it cannot be admitted from Mac headers alone.
