---
title: Use with Tauri
description: Run native or WebAssembly PostgreSQL in your Rust backend and expose commands to the webview.
---

Tauri desktop apps can use either [WASIX Rust](/docs/sdk/wasix-rust) for WebAssembly PostgreSQL or [native Rust](/docs/sdk/rust) for native PostgreSQL. Keep the database in Rust application state and expose operations such as adding or searching notes to the webview. Both Rust applications build as native desktop executables.

## WebAssembly PostgreSQL

Add `oliphaunt-wasix` to the Tauri Rust application's `Cargo.toml`:

```toml
[dependencies]
oliphaunt-wasix = "{{release:oliphaunt-wasix-rust}}"
```

Use `AsyncOliphaunt` to run database work on its dedicated owner thread. This helper opens persistent storage beneath the application's data directory:

```rust
use oliphaunt_wasix::{AsyncOliphaunt, DatabaseStorage};
use std::path::PathBuf;

struct AppDatabase(AsyncOliphaunt);

async fn open_database(app_data: PathBuf) -> oliphaunt_wasix::Result<AsyncOliphaunt> {
    let db = AsyncOliphaunt::builder()
        .storage(DatabaseStorage::Directory(app_data.join("postgres")))
        .open()
        .await?;
    db.execute("CREATE TABLE IF NOT EXISTS notes (body text NOT NULL)").await?;
    Ok(db)
}
```

## Native PostgreSQL

Alternatively, add `oliphaunt` using the [native Rust quickstart](/docs/sdk/rust). Use this helper in place of the WebAssembly helper above:

```rust
use oliphaunt::{AsyncOliphaunt, DatabaseStorage};
use std::path::PathBuf;

struct AppDatabase(AsyncOliphaunt);

async fn open_database(app_data: PathBuf) -> oliphaunt::Result<AsyncOliphaunt> {
    let db = AsyncOliphaunt::builder()
        .storage(DatabaseStorage::Directory(app_data.join("postgres")))
        .direct()
        .open()
        .await?;
    db.execute("CREATE TABLE IF NOT EXISTS notes (body text NOT NULL)").await?;
    Ok(db)
}
```

Both helpers expose the application operations below. Each uses its own PostgreSQL runtime; use a logical dump when moving existing data between them. Native direct mode binds the process to its first root, as described in [runtime modes](/docs/learn/native-runtime#direct).

## Open persistent application storage

During your existing Tauri builder's setup, resolve the directory and register the handle:

```rust
use tauri::Manager;

// Add this setup callback to your existing tauri::Builder.
.setup(|app| {
    let app_data = app.path().app_data_dir()?;
    let db = tauri::async_runtime::block_on(open_database(app_data))?;
    app.manage(AppDatabase(db));
    Ok(())
})
```

## Expose application commands

Use managed state in an async command, bind user values, and register the command with `tauri::generate_handler![add_note]`:

```rust
#[tauri::command]
async fn add_note(
    db: tauri::State<'_, AppDatabase>,
    body: String,
) -> Result<(), String> {
    db.0.execute_with_params("INSERT INTO notes (body) VALUES ($1)", [body])
        .await
        .map_err(|error| error.to_string())?;
    Ok(())
}
```

The webview calls the command through Tauri:

```ts
import { invoke } from '@tauri-apps/api/core';

await invoke('add_note', { body: 'First note' });
```

Validate inputs and expose only operations the frontend needs. Keep database paths and raw SQL out of the frontend command contract.

## Use a PostgreSQL driver or ORM

For WebAssembly PostgreSQL, add `oliphaunt-pgwire-server` using the [WASIX endpoint recipe](/docs/sdk/wasix-rust/runtime#local-postgresql-endpoint). Its `AsyncOliphauntServer` exposes a PostgreSQL URL for **one connected client at a time**. Configure pools with a maximum of one connection. The [WASIX Tauri example](https://github.com/f0rr0/oliphaunt/tree/main/src/examples/wasix/tauri) retains the server in application state alongside a one-connection SQLx pool.

For native PostgreSQL and independent client sessions, use `oliphaunt::AsyncOliphauntServer`. Return and retain the server handle:

```rust
use oliphaunt::AsyncOliphauntServer;

async fn start_server(app_data: PathBuf) -> oliphaunt::Result<AsyncOliphauntServer> {
    AsyncOliphauntServer::builder()
        .storage(DatabaseStorage::Directory(app_data.join("postgres")))
        .start()
        .await
}
```

Store the server alongside the application's driver or pool. Create the pool using `server.connection_string()`. During shutdown, close the pool before awaiting `server.close()`.

## Package and shut down

Ship the chosen runtime's host assets and matching extension packages with each desktop build. WASIX Rust includes platform-specific host resources, so check [supported desktop hosts](/docs/reference/capabilities#supported-webassembly-hosts). Test the packaged application; a development run may resolve files that are absent from the final bundle.

Stop accepting application work before closing the database. Await `db.close()` through your app's shutdown path to observe errors. Use the SDK's physical backup API for compatible restores within its runtime family and logical PostgreSQL tools for transfers between families.

See Tauri's [state management](https://v2.tauri.app/develop/state-management/) and [calling Rust](https://v2.tauri.app/develop/calling-rust/) documentation for application wiring.
