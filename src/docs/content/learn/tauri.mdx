# Tauri Usage

Use the Rust SDK from Tauri state. `oliphaunt` is the native SDK for Tauri and
Rust desktop apps; it owns direct embedded mode, broker mode, and server mode
over native PostgreSQL.

WASIX bindings are separate products. Native Tauri apps start with the native
Rust SDK unless they deliberately choose the Rust WASIX host.

## App Shape

Keep the database handle in Rust state and expose narrow Tauri commands to the
webview. The webview calls app-specific commands such as `add_item` or
`search_items`; Rust owns the storage directory, lock, runtime handle, lifecycle,
and backup APIs.

| Need | Recommended mode |
| --- | --- |
| One embedded app database with lowest overhead | `.direct()` |
| Multiple database instances or helper-process ownership | `.broker()` |
| SQLx pools, ORMs, `psql`, or `pg_dump` | `.open_server()` |

## Direct Rust State

Use `Oliphaunt` with direct execution when your Tauri commands own the database
calls and you want the lowest-latency embedded path:

```rust,no_run
use oliphaunt::Oliphaunt;
use tauri::State;

struct Db(Oliphaunt);

#[tauri::command]
async fn add_item(db: State<'_, Db>, value: String) -> Result<(), String> {
    db.0
        .execute_with_params("INSERT INTO items(value) VALUES ($1)", [value])
        .await
        .map_err(|err| err.to_string())?;
    Ok(())
}
```

Open the database under your app data directory during setup:

```rust,no_run
use oliphaunt::Oliphaunt;

async fn open_app_database(app_data_dir: std::path::PathBuf) -> oliphaunt::Result<Oliphaunt> {
    Oliphaunt::builder()
        .directory(app_data_dir.join("postgres"))
        .direct()
        .open()
        .await
}
```

Store the resulting `Oliphaunt` handle with `tauri::State`. Cloned SDK handles
share the same executor and session semantics; server mode is the path for
independent PostgreSQL client sessions.

## Existing Postgres Clients

Use `open_server()` when another Rust library expects a PostgreSQL URL, real
independent sessions, SQLx pools, `psql`, or `pg_dump`:

```rust,no_run
use oliphaunt::Oliphaunt;

async fn open_server_mode() -> oliphaunt::Result<String> {
    let server = Oliphaunt::builder()
        .directory("./.liboliphaunt")
        .open_server()
        .await?;

    Ok(server.connection_string().to_owned())
}
```

Use `.broker()` for desktop apps that want helper-process ownership or
multiple database instances managed by the Rust SDK.

## Extensions And Assets

Select exact SQL extension names in Rust configuration before opening the database.
Package only the extension artifacts your Tauri app uses, then verify the app
artifact before release. An app that selects `vector` ships `vector` and its
declared dependencies.

## Backup And Restore

Direct and broker databases expose one byte physical-backup API and static
restore into an absent or empty destination. Local server handles intentionally
omit SDK backup: use ordinary PostgreSQL `pg_basebackup` for physical backups or
plain `pg_dump`/`psql` for logical workflows through the connection string.

## Operational Guidance

- Use `.direct()` for one embedded PostgreSQL session with minimal overhead.
- Use `.broker()` when helper-process ownership matters more than direct
  call overhead.
- Use `.open_server()` for real concurrent PostgreSQL client sessions and pools.
- React Native apps use the React Native SDK, which delegates to Swift on
  iOS/macOS and Kotlin on Android.
