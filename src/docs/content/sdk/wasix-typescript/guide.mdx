These recipes build on the [WASIX TypeScript quickstart](/docs/sdk/wasix-typescript). An open `db` owns one PostgreSQL session on every supported host. See the [WebAssembly explanation](/docs/sdk#postgresql-as-webassembly) for how the runtime fits your application.

## Choose persistent storage

Import only the adapter for your host:

| Host | Import | Create storage |
| --- | --- | --- |
| Browser IndexedDB | `@oliphaunt/wasix-ts/storage/indexed-db` | `indexedDB('notes')` |
| Browser OPFS | `@oliphaunt/wasix-ts/storage/opfs` | `opfs('notes')` |
| Node.js / Electron | `@oliphaunt/wasix-ts/storage/node` | `directory('./data/notes')` |
| Bun | `@oliphaunt/wasix-ts/storage/bun` | `directory('./data/notes')` |
| Deno | `@oliphaunt/wasix-ts/storage/deno` | `directory('./data/notes')` |

For example, a Node.js application opens a persistent root with:

```ts
import Oliphaunt from '@oliphaunt/wasix-ts';
import { directory } from '@oliphaunt/wasix-ts/storage/node';

const db = await Oliphaunt.open({ storage: directory('./data/notes') });
```

Browser and JavaScript hosts can initialize storage through `initdb` when no seed is selected. For published browser Worker compatibility, follow [browser initialization](#initialize-browser-worker-storage) or the [quickstart](/docs/sdk/wasix-typescript#keep-browser-data-between-sessions). Existing browser storage does not require a seed.

Only one live owner may use a persistent root or browser storage name. Close the current handle before opening it from another Worker, process, or binding.

## Choose execution placement

| Import | Browser | Desktop host |
| --- | --- | --- |
| `@oliphaunt/wasix-ts` | Executes in the importing realm | Dedicated Rust owner keeps the event loop responsive |
| `@oliphaunt/wasix-ts/direct` | Unavailable | May block the calling JavaScript thread |
| `@oliphaunt/wasix-ts/worker` | Package-owned Worker | Package-owned JavaScript Worker |

The available placements return the same promise-based query API. An async signature alone does not mean that execution is off the calling thread. Use `/worker` in a browser UI that must remain responsive.

OPFS uses synchronous file access where the browser provides it in a Dedicated Worker. In a Window or a host without those handles, the adapter uses its portable persistence path automatically.

## Initialize browser Worker storage

The browser root import and the package-owned `/worker` host support `initdb` in the current source. A matching seed is optional and can speed up initialization.

The published `@oliphaunt/wasix-ts@0.2.2` browser Worker predates seed-free initialization. With that package, initialize fresh persistent storage through the root client, close it, then reopen it in the Worker, as shown in the [quickstart](/docs/sdk/wasix-typescript#keep-browser-data-between-sessions). Existing storage reopens without a seed.

For seeded initialization, supply an archive and manifest produced for the installed WASIX runtime. The seed's `runtime.product`, `runtime.version`, and physical compatibility must match the SDK's runtime; the seed package version alone does not establish compatibility. A mismatch fails with `WASIX seed has an incompatible runtime identity`.

The published `@oliphaunt/seed-wasix-standard@0.2.2` manifest targets runtime 0.3.0, while `@oliphaunt/wasix-ts@0.2.2` uses runtime 0.3.2. Use root initialization with those packages. Do not change a seed manifest to bypass validation.

When you have a compatible seed archive and manifest, serve both as application assets with the same cross-origin policies as the runtime. This fragment assumes those files are deployed at the URLs shown:

```ts
const db = await OliphauntWorker.open({
  storage: indexedDB('notes'),
  seed: {
    archive: '/assets/cluster-seed.tar.zst',
    manifest: '/assets/cluster-seed.json',
  },
});
```

It uses the Worker and IndexedDB imports from the quickstart. For ICU catalogs, provide the matching ICU seed and canonical ICU data too. Existing storage can reopen without a seed.

## Query and transact

```ts
await db.execute('CREATE TABLE IF NOT EXISTS notes (body text NOT NULL)');
await db.transaction(async (tx) => {
  await tx.execute('INSERT INTO notes (body) VALUES ($1)', ['First']);
  await tx.execute('INSERT INTO notes (body) VALUES ($1)', ['Second']);
});
console.log((await db.query('SELECT body FROM notes')).rows);
```

Return to commit and throw to roll back. Use only the callback's `tx` for its statements. Do not manually begin, end, or replace the outer transaction; use `tx.rollback()` for explicit rollback. Savepoints are supported.

Persistent operations publish their changes before their promises settle. A transaction publishes after confirmed commit or rollback. If publication fails, the handle becomes unusable: close it and reopen the last complete stored generation. The failed operation may have an uncertain outcome; inspect application state before retrying a write.

## Select extensions

Install a WASIX extension package and pass its descriptor, not a SQL-name string:

```sh
npm install @oliphaunt/extension-pgtap-wasix@{{release:oliphaunt-extension-pgtap}}
```

```ts
import pgtap from '@oliphaunt/extension-pgtap-wasix';

const db = await Oliphaunt.open({ extensions: [pgtap] });
await db.execute('CREATE EXTENSION IF NOT EXISTS pgtap');
```

Use the same selection when reopening extension-bearing data. The SDK does not run application migrations or `CREATE EXTENSION` automatically. Include the selected extension packages when deploying your app.

## Back up and restore

```ts
const archive = await db.backup();
await db.close();
await Oliphaunt.restore(directory('./data/restored'), archive);
const restored = await Oliphaunt.open({ storage: directory('./data/restored') });
await restored.close();
```

This fragment uses the Node.js `directory` adapter imported above. In a browser, pass a fresh IndexedDB or OPFS storage descriptor instead. Restore requires new or empty persistent storage and a compatible WASIX physical archive. Reapply required extensions when opening restored data.

## Use logical PostgreSQL tools

Install the optional tools package:

```sh
npm install @oliphaunt/wasix-tools@{{release:postgres-tools-wasix}}
```

```ts
import Oliphaunt from '@oliphaunt/wasix-ts';
import OliphauntWorker from '@oliphaunt/wasix-ts/worker';
import { indexedDB } from '@oliphaunt/wasix-ts/storage/indexed-db';
import { pgDump, psql } from '@oliphaunt/wasix-tools';

const sql = await pgDump(db);
const storage = indexedDB('import-' + crypto.randomUUID());
const initial = await Oliphaunt.open({ storage });
await initial.close();
const target = await OliphauntWorker.open({ storage });
try {
  await psql(target, { script: sql });
} finally {
  await target.close();
}
```

This browser fragment assumes an open source `db`. It initializes a fresh destination through the root client before the Worker imports SQL. On Node.js, Bun, Deno, and Electron, use `Oliphaunt.open()` for the target instead; those hosts support initialization and `psql` directly.

`pgDump` supports root, direct, and Worker handles. `psql` supports all desktop placements; in browsers it requires a Worker handle. A plain dump can contain COPY data and psql commands, so restore it with `psql`, not `execute`.

Tools exclusively use and reset the session. Reapply session settings and prepared statements after a tool run. Interactive psql, custom archives, parallel jobs, and `pg_restore` are outside this tools API.

## Open a local endpoint

On Node.js, Bun, Deno, or Electron, use the `/server` entry point:

```ts
import { openServer } from '@oliphaunt/wasix-ts/server';

const server = await openServer({
  storage: directory('./data/server'),
  listen: { transport: 'tcp' },
});
console.log(server.connectionString);
// Close the PostgreSQL client before awaiting server.close().
```

The endpoint accepts **one connected client at a time**. Configure a client pool with a maximum of one connection. Browser apps cannot use this TCP endpoint. Choose [native server mode](/docs/learn/native-runtime#server) when independent sessions are required through an SDK. Keep the server handle in application state, close client connections first, then await `server.close()`.

## Desktop host setup

The JavaScript host packages target macOS ARM64, Linux GNU x64/ARM64, and Windows MSVC x64. These hosts load a matching Node-API addon that runs WebAssembly PostgreSQL. Use the root import for a dedicated Rust owner thread; `/worker` creates a JavaScript Worker instead. This package does not imply support for arbitrary edge or hosted JavaScript environments.

Deno needs local npm module resolution. Set `"nodeModulesDir": "auto"` in `deno.json`, use `npm:` import prefixes, and grant native loading and storage permissions:

```sh
deno run --allow-ffi --allow-read --allow-write --allow-env main.ts
```

The Worker placement does not require process-spawn permission. For Node.js and Bun, use the normal package import and the matching directory adapter.

Electron runs database operations in its main process or an application-owned host Worker. Keep the database in application state and expose focused operations through IPC. Electron packaging must leave `**/prebuilds/**` unpacked and preserve native loader companions beside the addon in `app.asar.unpacked`.

## Errors and shutdown

Handle SQL failures using `PostgresError` and SQLSTATE. Transaction aggregates preserve callback and rollback/database failures. Await `close()` to observe cleanup; even a failed teardown makes the handle terminal. Close after a transaction callback settles, not from inside it.

There is no public direct-query cancellation API. Keep transactions and queries bounded, and select an execution placement that preserves application responsiveness.
