The Rust SDK targets Tauri apps, native Rust desktop apps, and Rust services
that want an embedded PostgreSQL runtime with explicit mode selection.

Use this SDK when your application is written in Rust or when a Tauri app keeps
database ownership in the Rust sidecar. It owns the full native runtime model:
direct calls for embedded latency, broker helpers for desktop robustness, and
server mode for normal PostgreSQL clients.

The root import is the synchronous caller-thread API. Import
`oliphaunt::worker` explicitly to give Oliphaunt a dedicated owner thread and
use async methods.

## Install

Add the crate to your Rust app:

```toml
[dependencies]
oliphaunt = "0.1"
```

## Open And Query

Then open a database in app-owned storage:

```rust
use oliphaunt::{Extension, Oliphaunt};

fn open_database() -> oliphaunt::Result<()> {
    let mut db = Oliphaunt::builder()
        .directory("./app-data/main.oliphaunt")
        .direct()
        .extension(Extension::Vector)
        .open()?;

    let rows = db.query("SELECT 1::text AS value")?;
    assert_eq!(rows.get_text(0, "value")?, Some("1"));
    db.close()?;
    Ok(())
}
```

For an async owner-thread handle, only the import and awaiting change:

```rust
use oliphaunt::worker::Oliphaunt;

async fn open_database() -> oliphaunt::Result<()> {
    let db = Oliphaunt::builder().temporary_directory().open().await?;
    let rows = db.query("SELECT 1::text AS value").await?;
    assert_eq!(rows.get_text(0, "value")?, Some("1"));
    db.close().await?;
    Ok(())
}
```

## Runtime Shape

Rust exposes the complete native mode model:

| Mode | Use it for |
| --- | --- |
| Native direct | Lowest-latency embedded PostgreSQL session |
| Native broker | Helper-process isolation and multi-instance desktop apps |
| Native server | `psql`, `pg_dump`, ORMs, pools, and independent clients |

Direct and broker mode serialize work through one physical PostgreSQL session.
Server mode is the mode for independent concurrent PostgreSQL clients.

Execution placement is orthogonal to those modes:

| Import | Calling contract | Ownership |
| --- | --- | --- |
| `oliphaunt::Oliphaunt` | Synchronous `&mut self` methods | Exclusive `!Send + !Sync` handle; work runs on the opening thread |
| `oliphaunt::worker::Oliphaunt` | Async methods returning `Send` futures | Cloneable `Send + Sync` handle; one dedicated owner thread and bounded FIFO |

The selected mode defines support. Use the static runtime support matrix when
choosing a mode; opened handles expose operations directly.

## App Responsibilities

- Use an app-owned directory for persistence. Omit storage configuration for an
  SDK-owned temporary directory.
- Select exact SQL extension names before opening the database.
- Use SDK backup and restore APIs for data movement instead of copying a live
  PostgreSQL directory.
- Use the worker API when an async executor must remain responsive.
- Use broker or server mode when process isolation or independent clients matter.
