Use `oliphaunt` for native desktop Rust and Tauri applications. Choose [WASIX Rust](/docs/sdk/wasix-rust) when you want to host the WebAssembly runtime instead.

## Install

Use Rust 1.93 or later. Add the crate to `Cargo.toml`:

```toml
[dependencies]
oliphaunt = "@VERSION(oliphaunt-rust)@"
```

## Configure the native runtime

The crate dependency alone is not enough to run native queries in @VERSION(oliphaunt-rust)@. Download the matching [native runtime archive](https://github.com/f0rr0/oliphaunt/releases/tag/liboliphaunt-native-v@VERSION(liboliphaunt-native)@), preserve its complete directory structure, and set the runtime paths before launching your app.

For Linux x64 GNU, run these commands from your Rust application's directory:

```sh
mkdir -p oliphaunt-resources/native-runtime/liboliphaunt-native
curl -fL https://github.com/f0rr0/oliphaunt/releases/download/liboliphaunt-native-v@VERSION(liboliphaunt-native)@/liboliphaunt-@VERSION(liboliphaunt-native)@-linux-x64-gnu.tar.gz -o oliphaunt-runtime.tar.gz
tar -xzf oliphaunt-runtime.tar.gz -C oliphaunt-resources/native-runtime/liboliphaunt-native
export OLIPHAUNT_RESOURCES_DIR="$PWD/oliphaunt-resources"
export LIBOLIPHAUNT_PATH="$OLIPHAUNT_RESOURCES_DIR/native-runtime/liboliphaunt-native/lib/liboliphaunt.so"
```

Select your platform's archive on other supported desktop targets and point `LIBOLIPHAUNT_PATH` to its dynamic library. Keep the runtime, cluster seeds (including empty directories), and libraries together. The resource directory is separate from your application's database storage. Your application launcher must provide these environment variables on subsequent runs too.

In 0.2.0, `register_build_resources!()` fails to compile outside the SDK, and Cargo-staged cluster seeds can omit required empty directories. The archive setup above avoids those paths; do not replace it with build-helper registration alone.

## Run your first query

Create `src/main.rs` with a complete, synchronous example:

<!-- oliphaunt-snippet: oliphaunt-rust -->

```rust
use oliphaunt::Oliphaunt;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut db = Oliphaunt::open()?;
    let result = db.sql("SELECT $1::int4 AS answer").bind(42_i32).query()?;
    let answer: i32 = result.rows()[0].try_get("answer")?;
    println!("{answer}"); // 42
    db.close()?;
    Ok(())
}
```

Run it with `cargo run`. The default database uses a temporary directory and is removed when its owner closes.

## Keep data between runs

Use this storage configuration instead of the disposable example above. Direct mode stays bound to its first root for the lifetime of the process; closing does not let the same process switch roots.

Open a stable directory for application data:

```rust
use oliphaunt::{DatabaseStorage, Oliphaunt};

let mut db = Oliphaunt::builder()
    .storage(DatabaseStorage::Directory("./app-data/main.oliphaunt".into()))
    .direct()
    .open()?;
```

Keep the handle in application state. Reopen the same path to access the data again.

## Use an async application

Use `AsyncOliphaunt` when queries must not block an async executor:

```rust
use oliphaunt::AsyncOliphaunt;

let db = AsyncOliphaunt::open().await?;
let result = db.query("SELECT 42::int4 AS answer").await?;
db.close().await?;
```

The synchronous handle is `Send` but not `Sync`; it requires exclusive access. The async handle is cloneable, `Send`, and `Sync`. Clones share one session and execute work in order.
