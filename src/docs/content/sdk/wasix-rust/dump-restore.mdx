# Rust WASIX Dump, Restore, And Upgrade

`oliphaunt-wasix` uses the WASIX `pg_dump` binary from the shipped portable
runtime asset for portable SQL exports, restores, and version-to-version
upgrades.

<Callout type="info" title="Rust-only data-movement APIs">
This page documents `oliphaunt-wasix`. The
[WASIX TypeScript binding](/docs/sdk/wasix-typescript) exposes the shared WASIX
physical archive, but not the Rust-only `pg_dump`, `psql`, or server tool APIs.
</Callout>

<WasmDataMovement />

## Choose The Right Export Format

Use logical dumps when you need:

- a portable SQL export;
- an upgrade path between `oliphaunt-wasix` releases;
- a way to move data between different stores safely.

Use physical archives when you need:

- a same-version clone;
- a same-runtime restore into another `oliphaunt-wasix` store;
- a fast local backup of the current cluster state.

Use logical dumps for cross-version upgrades. Keep physical archives for
same-version clones and restores.

## Tool API

Enable the `tools` feature for `PgDumpOptions`, `PsqlOptions`,
`OliphauntServer::pg_dump()`, and `OliphauntServer::psql()`:

```toml
[dependencies]
oliphaunt-wasix = { version = "0.1", features = ["tools"] }
```

Start a TCP `OliphauntServer` and dump it to SQL:

```rust,no_run
use oliphaunt_wasix::{PgDumpOptions, OliphauntServer};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let server = OliphauntServer::builder().start()?;

    let sql = server.pg_dump(PgDumpOptions::new().arg("--schema-only"))?;
    assert!(!sql.is_empty());

    server.close()?;
    Ok(())
}
```

The packaged tools currently require the server's TCP endpoint. Release any
other connected client first because this server deliberately serves one client
session at a time. The tools are not methods on the direct `Oliphaunt` handle.
`pg_dump()` returns UTF-8 SQL text;
`psql()` returns UTF-8 standard output. Use `PsqlOptions::command(...)` for one
command or `PsqlOptions::script(...)` for a complete SQL script. `pg_dump()`
returns standard PostgreSQL 18 plain-text output unchanged, including its
`COPY` data and `\\restrict`/`\\unrestrict` security delimiters.

## `PgDumpOptions`

`PgDumpOptions` controls the managed parts of the dump command:

```rust,no_run
use oliphaunt_wasix::PgDumpOptions;

let options = PgDumpOptions::new()
    .username("postgres")
    .database("template1")
    .args(["--schema-only", "--quote-all-identifiers"]);
```

Useful passthrough flags include dump-shaping options such as:

- `--schema-only`
- `--quote-all-identifiers`
- `-n <schema>`
- `-t <table>`

Managed connection and output flags are reserved by the API:
`--file`, `--format`, `--compress`, `--encoding`, `--host`, `--port`,
`--username`, `--dbname`, and `--jobs` are configured by Oliphaunt instead of
`arg(...)` or `args(...)`. The returned script is always uncompressed UTF-8
plain text.

## CLI

The CLI is also part of the crate's `tools` feature.

Dump a persistent directory:

```sh
oliphaunt-wasix-dump --directory ./.oliphaunt
```

Select a non-default database or user with `--database` and `--username`. If
the root uses installed extensions, repeat `--extension NAME` for every
extension that must be mounted before PostgreSQL starts:

```sh
oliphaunt-wasix-dump --directory ./.oliphaunt \
  --database app --username owner \
  --extension vector --extension pg_trgm
```

Pass through normal `pg_dump` shaping flags after `--`:

```sh
oliphaunt-wasix-dump --directory ./.oliphaunt -- --schema-only
oliphaunt-wasix-dump --directory ./.oliphaunt -- --quote-all-identifiers
```

## Restore

For same-version physical copies, use direct `backup()` and static
`Oliphaunt::restore(destination, bytes)`. Physical restore accepts an absent or
empty managed-root directory and publishes a new root only after validating and
staging the complete archive.

For a logical restore, connect a standard PostgreSQL client to
`server.connection_string()` and feed it the `pg_dump` SQL using that client's
normal script/input API, or run the packaged tool with
`server.psql(PsqlOptions::new().script(sql))`. Do not pass the script to the
direct database `execute` method: plain `pg_dump` output includes `psql` meta
commands. Oliphaunt does not expose a second logical-restore abstraction.

## Upgrade Guidance

Use logical dump and restore when upgrading between `oliphaunt-wasix` versions or
changing shipped runtime assets:

1. Open the old database with the old crate/runtime.
2. Start a TCP `OliphauntServer` and create a logical dump with
   `server.pg_dump(...)`, or use `oliphaunt-wasix-dump`.
3. Start a fresh TCP `OliphauntServer` with the new crate/runtime.
4. Feed the script through `server.psql(PsqlOptions::new().script(sql))` or
   another standard PostgreSQL client's script API.

Use logical dumps for general upgrades. Physical data-dir archives are for the
same runtime family and database format.
