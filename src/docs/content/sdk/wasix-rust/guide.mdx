# Build With Rust WASIX

Use `oliphaunt-wasix` when Rust owns the WASIX host. This crate is separate
from every native SDK and from the WASIX TypeScript binding.

<Callout type="info" title="This is the Rust binding">
Browser, Node, Bun, and Deno TypeScript applications use [`@oliphaunt/wasix-ts`](/docs/sdk/wasix-typescript). The Rust
and TypeScript bindings consume the portable WASIX runtime family. Their APIs
follow the same conceptual rule: the root runs directly in the calling
thread/realm, while an explicit worker entry point opts into a dedicated
package-owned execution context. Signatures remain idiomatic to each language.
</Callout>

<SdkGuideSummary id="wasix-rust" />

<Steps>
<Step>

### Install

Add the Rust binding. The package resolves its matching portable runtime and
host AOT artifacts; application code does not configure archive URLs.

```sh
cargo add oliphaunt-wasix
```

</Step>
<Step>

### Open and query

Omitting storage opens a fresh in-memory database initialized from the packaged
cluster seed. The crate root returns an exclusive direct handle; fallible
database operations are synchronous and take `&mut self`.

<!-- oliphaunt-snippet: oliphaunt-wasix-rust -->

```rust
use oliphaunt_wasix::Oliphaunt;

fn run() -> oliphaunt_wasix::Result<()> {
    let mut database = Oliphaunt::open()?;
    let result = database.query("SELECT 1::text AS value")?;

    let value: &str = result.rows()[0].try_get("value")?;
    assert_eq!(value, "1");
    database.close()?;
    Ok(())
}
```

</Step>
<Step>

### Create app data

Use ordinary PostgreSQL SQL and positional parameters:

```rust
database.execute(
    "CREATE TABLE IF NOT EXISTS notes (id bigserial PRIMARY KEY, title text NOT NULL)",
)?;
database.execute_with_params(
    "INSERT INTO notes (title) VALUES ($1)",
    ["First note"],
)?;

let notes = database.query_with_params(
    "SELECT id, title FROM notes ORDER BY id DESC LIMIT $1",
    [20_i32],
)?;
let first_title: String = notes.rows()[0].try_get("title")?;
```

</Step>
<Step>

### Configure

Select persistence only when the application needs it:

```rust
use oliphaunt_wasix::{DatabaseStorage, Oliphaunt};

let mut database = Oliphaunt::builder()
    .storage(DatabaseStorage::Directory("./app-data/main".into()))
    .open()?;
```

`DatabaseStorage::Memory` is the default. `Directory` uses a caller-owned host
directory; applications resolve temporary or platform app-data paths with
their preferred host library. New stores use the packaged cluster seed.

</Step>
<Step>

### Choose execution placement

Use the root `Oliphaunt` for the normal direct contract. PostgreSQL runs on the
calling thread with no SDK queue or message hop. Database and transaction
methods take `&mut self`:

```rust
use oliphaunt_wasix::Oliphaunt;

fn run_direct() -> oliphaunt_wasix::Result<()> {
    let mut database = Oliphaunt::open()?;
    database.execute("CREATE TABLE notes (title text NOT NULL)")?;
    database.close()
}
```

Use `oliphaunt_wasix::worker::Oliphaunt` when an async application needs a
cloneable `Send + Sync` handle and dedicated owner-thread execution:

```rust
use oliphaunt_wasix::worker::Oliphaunt;

async fn run_on_worker() -> oliphaunt_wasix::Result<()> {
    let database = Oliphaunt::open().await?;
    database.execute("CREATE TABLE notes (title text NOT NULL)").await?;
    database.close().await
}
```

Use the root `OliphauntServer` only when an existing PostgreSQL client library
needs a local connection URL. Its `start()` and `close()` lifecycle is
synchronous, while its listener thread owns the single-backend wire server.
`worker::OliphauntServer` offers the same server with async lifecycle calls.
Neither is an alias for native direct, broker, or server topology.

</Step>
<Step>

### Handle lifecycle

Close the root database explicitly with `close()`. Once shutdown starts, the
handle is permanently retired: `is_closed()` is true, later work is rejected,
and later close calls replay the terminal result. Callback transactions roll
back before resuming a callback panic and poison the database if rollback is
uncertain. The direct server keeps its handle across `close(&mut self)`, exposes
`is_closed()`, and replays its first terminal close result.

On a worker handle, `close().await` establishes an ordered FIFO cutoff. Work
admitted earlier drains and later work is rejected. Concurrent close callers
receive the same result. Dropping the last clone starts best-effort cleanup but
does not wait for it, so explicit close remains the durable lifecycle boundary.

Persistent directories have exclusive ownership: a second database or server
open against the same directory returns a lock error instead of starting
another backend.

</Step>
<Step>

### Select extensions

Enable only the exact Cargo features the application uses, then select the
matching typed extension value on the builder. Optional extension payloads are
not part of the core runtime.

```toml
[dependencies]
oliphaunt-wasix = { version = "0.1", features = ["extension-pgtap"] }
```

```rust
use oliphaunt_wasix::{extensions::PGTAP, Oliphaunt};

let mut database = Oliphaunt::builder().extension(PGTAP).open()?;
```

</Step>
<Step>

### Back up, dump, and restore

Use `backup()` and static `Oliphaunt::restore(destination, bytes)` for the one
same-version WASIX physical archive. Enable the crate's `tools` feature for
`pg_dump` and `psql` when portable logical SQL or version upgrades are needed.
Do not copy a live PostgreSQL directory.

```rust
let archive = database.backup()?;
database.close()?;
Oliphaunt::restore("./app-data/restored", archive)?;
```

</Step>
<Step>

### Use transactions

The direct callback receives an exclusive `&mut Transaction`. Success commits,
callback failure rolls back, and `rollback()` explicitly rolls back without a
later commit:

```rust
database.transaction(|transaction| {
    transaction.execute_with_params(
        "INSERT INTO notes (title) VALUES ($1)",
        ["Transactional note"],
    )?;

    let count = transaction.query("SELECT count(*)::int8 AS count FROM notes")?;
    let count: i64 = count.rows()[0].try_get("count")?;
    assert!(count > 0);
    Ok(())
})?;
```

The transaction borrow prevents unrelated direct work until the callback
settles. Under `worker`, the callback is async and receives a shared
`&worker::Transaction`; work through another database clone is rejected while
the transaction is pinned. Dropping an active worker transaction future queues
best-effort rollback in FIFO order.

</Step>
</Steps>

## Troubleshooting

Check whether the selected managed root is new or complete, the packaged
cluster seed and exact runtime/AOT asset pair, enabled extension features,
directory ownership, and SQLSTATE-bearing
PostgreSQL errors. Browser, Node, Bun, and Deno direct/Worker behavior, the
explicit `/worker` entry point, IndexedDB, and recovery behavior are documented
on the [WASIX TypeScript guide](/docs/sdk/wasix-typescript/guide).
