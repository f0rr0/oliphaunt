# Build With Rust WASIX

Use `oliphaunt-wasix` when Rust owns the WASIX host. This crate is separate
from every native SDK and from the WASIX TypeScript binding.

<Callout type="info" title="This is the Rust binding">
Browser, Node, Bun, and Deno TypeScript applications use [`@oliphaunt/wasix-ts`](/docs/sdk/wasix-typescript). The Rust
and TypeScript bindings consume the portable WASIX runtime family, but they do not
promise the same public API.
</Callout>

<SdkGuideSummary id="wasix-rust" />

<Steps>
<Step>

### Install

Add the Rust binding. The package resolves its matching portable runtime and
host AOT artifacts; application code does not configure archive URLs.

```sh
cargo add oliphaunt-wasix
```

</Step>
<Step>

### Open and query

Omitting storage opens a fresh in-memory database initialized from the packaged
cluster seed.

<!-- oliphaunt-snippet: oliphaunt-wasix-rust -->

```rust
use oliphaunt_wasix::Oliphaunt;

fn main() -> anyhow::Result<()> {
    let mut database = Oliphaunt::open()?;
    let result = database.query("SELECT 1::text AS value")?;

    assert_eq!(result.get_text(0, "value")?, Some("1"));
    database.close()?;
    Ok(())
}
```

</Step>
<Step>

### Create app data

Use ordinary PostgreSQL SQL and positional parameters:

```rust
database.execute(
    "CREATE TABLE IF NOT EXISTS notes (id bigserial PRIMARY KEY, title text NOT NULL)",
)?;
database.execute_with_params(
    "INSERT INTO notes (title) VALUES ($1)",
    ["First note"],
)?;

let notes = database.query_with_params(
    "SELECT id, title FROM notes ORDER BY id DESC LIMIT $1",
    [20_i32],
)?;
```

</Step>
<Step>

### Configure

Select persistence only when the application needs it:

```rust
use oliphaunt_wasix::{DatabaseStorage, Oliphaunt};

let database = Oliphaunt::builder()
    .storage(DatabaseStorage::Directory("./app-data/main".into()))
    .open()?;
```

`DatabaseStorage::Memory` is the default. `Directory` uses a caller-owned host
directory; applications resolve temporary or platform app-data paths with
their preferred host library. New stores use the packaged cluster seed.

</Step>
<Step>

### Choose a mode

Use `Oliphaunt` for direct Rust calls. Use `OliphauntServer` only when an
existing PostgreSQL client library needs a local connection URL. These are Rust
WASIX APIs, not aliases for native direct, broker, or server modes.

</Step>
<Step>

### Handle lifecycle

Close the database explicitly. Persistent directories have exclusive ownership:
a second direct or server open against the same directory returns a lock error
instead of starting another backend.

</Step>
<Step>

### Select extensions

Enable only the exact Cargo features the application uses, then select the
matching typed extension value on the builder. Optional extension payloads are
not part of the core runtime.

```toml
[dependencies]
oliphaunt-wasix = { version = "0.1", features = ["extension-pgtap"] }
```

```rust
use oliphaunt_wasix::{extensions::PGTAP, Oliphaunt};

let database = Oliphaunt::builder().extension(PGTAP).open()?;
```

</Step>
<Step>

### Back up, dump, and restore

Use `backup()` and static `Oliphaunt::restore(destination, bytes)` for the one
same-version WASIX physical archive. Enable the crate's `tools` feature for
`pg_dump` and `psql` when portable logical SQL or version upgrades are needed.
Do not copy a live PostgreSQL directory.

</Step>
</Steps>

<SdkGuideProof id="wasix-rust" />

## Troubleshooting

Check whether the selected managed root is new or complete, the packaged
cluster seed and exact runtime/AOT asset pair, enabled extension features,
directory ownership, and SQLSTATE-bearing
PostgreSQL errors. Browser, Node, Bun, and Deno direct/Worker placement, IndexedDB, and
recovery behavior are documented on the
[WASIX TypeScript guide](/docs/sdk/wasix-typescript/guide).
