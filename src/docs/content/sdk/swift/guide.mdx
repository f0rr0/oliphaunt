# Build With Swift

Use the Swift SDK in iOS and macOS apps. It wraps the native runtime behind
Swift async APIs and keeps database work off the main actor.

<Callout type="info" title="Apple apps start with Swift APIs">
React Native on Apple platforms delegates runtime behavior through this SDK, but
Swift and SwiftUI apps use `OliphauntDatabase` directly.
</Callout>

<SdkGuideSummary id="swift" />

<Steps>
<Step>

### Install

Add the Swift package in Xcode or `Package.swift`. The package includes the
Swift API plus the platform runtime artifacts required for the selected target.

```swift
dependencies: [
    .package(url: "https://github.com/f0rr0/oliphaunt.git", from: "0.6.1")
]
```

Persistent storage lives under your app container. App users install your app; the
SDK package carries the runtime files it needs.

</Step>
<Step>

### Open and query

Open an `OliphauntDatabase` with a persistent file URL, run SQL with async calls, and
close when the app no longer needs the handle.

<!-- oliphaunt-snippet: oliphaunt-swift -->

```swift
let appSupport = FileManager.default.urls(
    for: .applicationSupportDirectory,
    in: .userDomainMask
)[0]

let database = try await OliphauntDatabase.open(
    configuration: OliphauntConfiguration(
        storage: .directory(appSupport.appending(path: "main.oliphaunt")),
        extensions: ["vector"]
    )
)

let rows = try await database.query("SELECT 1::text AS value")
let value = try rows.getText(row: 0, column: "value")

try await database.close()
```

Keep one database handle in app state and share it through your app's dependency
model. The handle owns a serialized session boundary.

</Step>
<Step>

### Create app data

Use async SQL helpers for application data. A SwiftUI model or app service can
own the database handle and expose app-specific methods:

```swift
try await database.execute("""
CREATE TABLE IF NOT EXISTS notes (
    id bigserial PRIMARY KEY,
    title text NOT NULL,
    body text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
)
""")

try await database.query(
    "INSERT INTO notes (title, body) VALUES ($1, $2) RETURNING id::text AS id",
    parameters: [
        .text("First note"),
        .text("Stored by embedded PostgreSQL")
    ]
)

let notes = try await database.query(
    "SELECT id, title FROM notes ORDER BY id DESC LIMIT 20"
)
```

Keep UI updates on the main actor, but keep database work behind the SDK's async
database actor.

</Step>
<Step>

### Configure

Configure storage, selected exact extensions, startup identity, and PostgreSQL
startup GUCs through the Swift configuration API. Storage defaults to
`.temporaryDirectory`; choose `.directory(url)` for persistence. Advanced
resource overrides retain packaged defaults for normal apps.

</Step>
<Step>

### Choose a mode

Native direct is the Apple runtime. It uses one resident backend per app process
and one physical session.

</Step>
<Step>

### Handle lifecycle

Swift exposes lifecycle as async API over a serial execution model. Use
`checkpoint()`, `cancel()`, and `close()` explicitly when app lifecycle policy
requires them.

</Step>
<Step>

### Select extensions

Select exact SQL extension names in app configuration. The app bundle contains
selected extension artifacts plus required dependencies. `CREATE EXTENSION`
succeeds when the selected runtime resources contain that extension for the
Apple target.

</Step>
<Step>

### Back up and restore

Use `backup()` and static `restore(destination:bytes:)` with app-owned file
URLs. Restore accepts a new or existing-empty destination and rejects nonempty
data without mutation.

</Step>
</Steps>

<SdkGuideProof id="swift" />

## Troubleshooting

Most Apple failures come from invalid file URLs, missing runtime resources, storage
locks, runtime errors, or extension selection mismatches. PostgreSQL
errors preserve SQLSTATE where the backend returns it.
