Use `@oliphaunt/react-native` with React Native's New Architecture on iOS or Android. The current package requires React Native 0.85+ and React 19+. Expo integration requires Expo 56+ and a native development or production build; Expo Go does not include this native module.

## Install and build

```sh
npm install @oliphaunt/react-native@@VERSION(oliphaunt-react-native)@
```

For an Expo app, add the config plugin:

```json title="app.json"
{
  "expo": {
    "plugins": ["@oliphaunt/react-native"]
  }
}
```

Build the native app for the platform you are testing:

<Tabs items={["iOS", "Android"]}>
<Tab value="iOS">

```sh
npx expo run:ios
```

</Tab>
<Tab value="Android">

```sh
npx expo run:android
```

</Tab>
</Tabs>

If you manage native projects directly, integrate the package's iOS CocoaPods and Android Gradle setup as described in [native integration](/docs/sdk/react-native/architecture). Rebuild after changing native resources or extensions.

## Run your first query

Call this function from application initialization or a user action, not during React rendering:

<!-- oliphaunt-snippet: oliphaunt-react-native -->

```ts
import Oliphaunt from '@oliphaunt/react-native';

export async function firstQuery() {
  const db = await Oliphaunt.open();
  try {
    const result = await db.query('SELECT $1::int4 AS answer', [42]);
    console.log(result.rows[0]?.answer); // 42
  } finally {
    await db.close();
  }
}
```

## Keep data between launches

Use this storage configuration instead of the disposable example above. Direct mode stays bound to its first root for the lifetime of the process; closing does not let the same process switch roots.

Let the platform SDK choose an app-private directory by name:

```ts
const db = await Oliphaunt.open({
  storage: { kind: 'applicationData', name: 'main' },
});
```

Keep this handle in an application service. Reopen the same name to use its data again. The default temporary storage is disposable.
