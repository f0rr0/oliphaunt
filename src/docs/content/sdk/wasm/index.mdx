`oliphaunt-wasix` is the Rust binding for the portable WASIX runtime. It keeps
its package, runtime assets, extensions, storage, and behavior separate from
the native SDK products.

Use this SDK when Rust owns the WASIX host. Native desktop and mobile apps use
native SDKs when they select `liboliphaunt`. Browser, Node, Bun, and Deno TypeScript apps can use the
separate [`@oliphaunt/wasix-ts` TypeScript binding](./browser-typescript); the two
WASIX bindings share portable runtime carriers, not a public API.

## Install

Install the Rust WASIX package. Consumer applications receive the matching
portable runtime and target AOT artifacts through package-manager dependencies.

For Rust hosts:

```sh
cargo add oliphaunt-wasix
```

## Open And Query

Open the direct Rust API for ordinary embedded use. Storage defaults to a true
in-memory WASIX filesystem:

```rust
use oliphaunt_wasix::{DatabaseStorage, Oliphaunt};

fn main() -> anyhow::Result<()> {
    let mut database = Oliphaunt::open()?;
    let rows = database.query("select 1::text as value", &[], None)?;

    // For persistence, select a caller-owned host directory instead:
    // let mut database = Oliphaunt::builder()
    //     .storage(DatabaseStorage::Directory("./app-data/main.oliphaunt".into()))
    //     .open()?;

    assert_eq!(rows.rows[0]["value"].as_str(), Some("1"));
    database.close()?;
    Ok(())
}
```

## Runtime Shape

Rust WASIX is separate from native direct, native broker, and native server. It
has its own filesystem, startup, server/proxy, dump/restore, and extension
behavior.

The Rust binding can expose direct APIs or a local PostgreSQL-compatible URL.
Those Rust-only server and dump APIs must not be inferred for the
TypeScript binding, whose intentionally smaller surface is documented on its
own page.

## App Responsibilities

- Depend on the portable runtime artifact and target-specific AOT artifact for
  each supported host.
- Install exact WASIX extension packages for the SQL extensions your app uses.
- Use the WASIX runtime guide for storage, server/proxy, and startup behavior.
- Use dump and restore flows for portable data movement and upgrades.
- Do not mix the crate's server, transaction, dump, or capability APIs into
  WASIX TypeScript examples.
