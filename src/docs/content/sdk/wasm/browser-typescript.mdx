# WASIX TypeScript

`@oliphaunt/wasix-ts` runs the portable WASIX runtime with worker isolation by
default or direct execution on request in browsers and Node.js. The same import
and database API work in every placement;
package exports select the host adapter. It is separate from native
`@oliphaunt/ts`: neither package imports, falls back to, or chooses the other at
runtime. Applications do not configure runtime archive, PGDATA template,
manifest, or host URLs.

## Browser requirements

Serve the application with cross-origin isolation and let the bundler preserve
the package's module-Worker edge:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

The package checks `crossOriginIsolated` before opening. Worker and runtime
subresources must also satisfy the page's COEP policy.

## Browser execution placement

Worker isolation is the default because runtime preparation, PostgreSQL work,
extension setup, and persistent snapshots stay outside the caller's JavaScript
agent. Select direct placement through the same `open()` API when latency
matters more than event-loop responsiveness:

```ts
await using database = await Oliphaunt.open({ execution: 'direct' });
const result = await database.query('select $1::int + 1 as answer', [41]);
console.log(result.getText(0, 'answer'));
```

`execution` describes host placement, not a second PostgreSQL engine. Both
values return `OliphauntDatabase`. Direct placement constructs PostgreSQL
asynchronously in the calling realm, then invokes it on the calling stack and
creates no Web Worker. Each database call
blocks that JavaScript agent until PostgreSQL returns, and cross-origin
isolation remains required. Separate memory or persistent-store identities can
remain open in either browser placement, although direct calls share one event
loop. Native extension side modules over Chromium's 8 MiB synchronous-module
limit require worker placement only when the carrier has no other unsupported
host requirement. The current PostGIS carrier also requires native load-order
handling and is therefore unsupported in both browser placements.

## Node.js

Node.js uses the same consumer code, defaults to memory and worker placement,
and accepts `execution: 'direct'` when blocking the calling thread is an
appropriate latency tradeoff. No browser headers, host option, or Node-specific
subpath is required:

```ts
import Oliphaunt from '@oliphaunt/wasix-ts';
import pgtap from '@oliphaunt/extension-pgtap-wasix';

const database = await Oliphaunt.open({ extensions: [pgtap] });
const result = await database.query('select 40 + 2 as answer');
console.log(result.getText(0, 'answer'));
await database.close();
```

Importing the IndexedDB adapter is valid package resolution on Node, but passing
it to `open()` fails before a worker starts. Use the Node-only directory adapter
when checkpoint/clean-close snapshot persistence fits the application.

Persistent Node storage is a selective import:

```ts
import Oliphaunt from '@oliphaunt/wasix-ts';
import { directory } from '@oliphaunt/wasix-ts/storage/node';

const storage = directory('./data/notes');
let database = await Oliphaunt.open({ storage });
await database.query('create table if not exists note (title text not null)');
await database.query('insert into note values ($1)', ['Persist this']);
await database.close();

database = await Oliphaunt.open({ storage });
console.log((await database.query('select * from note')).rows.length);
await database.close();
```

The adapter hydrates PGDATA into Wasmer memory and atomically publishes a whole
directory generation on `checkpoint()` and clean `close()`. It validates the
exact runtime and extension identity on reopen and locks one path to one worker
or process. Linux lease identity includes the host, boot, and PID namespace;
only locally proven-dead owners are reaped, while foreign/shared scopes fail
closed as `busy`. It is not a direct mount: termination can lose work since the
last checkpoint.

## Open with memory and one extension

Memory is the default, so an ordinary application supplies only the extensions
it uses:

```ts
import Oliphaunt from '@oliphaunt/wasix-ts';
import pgtap from '@oliphaunt/extension-pgtap-wasix';

const database = await Oliphaunt.open({
  extensions: [pgtap],
});

const result = await database.query('select pgtap_version() as version');
console.log(result.getText(0, 'version'));

await database.close();
```

Each `open()` without `storage` creates an independent database that disappears
on close. The extension is present because its WASIX descriptor was imported
and selected; the core runtime does not include every extension.

## Run an atomic transaction

The callback transaction reserves the database's PostgreSQL session from
`BEGIN` through `COMMIT`, so concurrent database calls cannot interleave:

```ts
const count = await database.transaction(async (tx) => {
  await tx.query('insert into note (title) values ($1)', ['Atomic work']);
  return tx.query('select count(*)::int4 as count from note');
});
```

Concurrent calls queued outside the callback wait behind the transaction. Use
the provided `tx` handle inside the callback; database-level calls reject there
instead of deadlocking. A rejected callback or failed `COMMIT` automatically
attempts `ROLLBACK` without masking the original failure. The handle rejects
further work after the callback finishes. `OliphauntDatabase` also implements
`AsyncDisposable`, enabling `await using` in TypeScript projects that use
explicit resource management.

## Opt into IndexedDB

Import persistence separately when checkpoint and clean-close snapshots match
the application's durability needs:

```ts
import Oliphaunt from '@oliphaunt/wasix-ts';
import pgtap from '@oliphaunt/extension-pgtap-wasix';
import { indexedDB } from '@oliphaunt/wasix-ts/storage/indexed-db';

const storage = indexedDB('notes');

let database = await Oliphaunt.open({ storage, extensions: [pgtap] });
await database.query(
  'create table if not exists note (id bigint generated always as identity, title text not null)',
);
await database.query('insert into note (title) values ($1)', ['Write the docs']);

await database.checkpoint();
await database.close();

database = await Oliphaunt.open({ storage, extensions: [pgtap] });
const notes = await database.query('select id, title from note order by id');
console.log(notes.rows.length);
await database.close();
```

`checkpoint()` first reaches PostgreSQL `ReadyForQuery`, then atomically
publishes a complete PGDATA generation. A successful `close()` publishes once
more. Browser or Worker termination can lose changes after the last published
generation; this is snapshot persistence, not per-transaction crash durability.
Only one open database may own a named IndexedDB database at a time.

Reopen with the same runtime and exact extension selection. A missing, added,
or changed carrier fails closed until an explicit extension-migration contract
exists.

## Recover from errors

SQL errors are ordinary `PostgresError` values with PostgreSQL fields such as
`sqlstate`. The binding consumes the response through `ReadyForQuery`, so the
same database remains usable:

```ts
import { PostgresError } from '@oliphaunt/wasix-ts';

try {
  await database.query('select 1 / 0');
} catch (error) {
  if (!(error instanceof PostgresError)) throw error;
  console.error(error.sqlstate); // 22012
}

const recovered = await database.query('select 40 + 2 as answer');
console.log(recovered.getText(0, 'answer')); // 42
```

PostgreSQL startup rejections from `Oliphaunt.open()`, such as SQLSTATE `3D000`
for a missing database, use the same `PostgresError` type and fields. A startup
error does not return a database handle to recover; correct the option and open
again.

Persistence and ownership failures are separate `WasixStorageError` values.
Inspect `code` and `durability`; after a checkpoint publication failure, close
the poisoned handle and reopen the last complete generation before deciding how
to reconcile application work. A host or transport failure is not a SQL error
and also requires a new handle.

## Public API boundary

The binding intentionally exposes one small asynchronous surface on both hosts:

| API | Purpose |
| --- | --- |
| `Oliphaunt.open(options?)` | Open one database with worker or direct placement |
| `database.query(sql, parameters?)` | Run a typed row query |
| `database.execute(sql)` | Execute SQL and return raw response bytes |
| `database.execProtocolRaw(bytes)` | Drive advanced PostgreSQL protocol traffic |
| `database.transaction(callback)` | Run a callback-scoped transaction with automatic commit or rollback |
| `database.checkpoint()` | Publish the selected persistent storage generation |
| `database.close()` | Terminate PostgreSQL and release the host/storage lease |
| `await using database = …` | Close through `Symbol.asyncDispose` at scope exit |

It does not expose `engine_capabilities()`, server/proxy, protocol streaming,
physical archive, logical dump/restore, or direct host-directory APIs.

Lifecycle semantics are fixed rather than dynamically reported:
`multipleInstances = true` for databases using memory or distinct persistent
store identities in every supported placement,
`sameInstanceLogicalReopen = false`, `instanceSwitchable = true`, and
`crashRestartable = false`. A given IndexedDB name or Node directory remains
exclusively leased despite support for separate instances.

## Current host boundary

IndexedDB is the only persistent browser adapter. OPFS is intentionally absent,
and omitted storage already covers temporary in-memory use. Node offers direct
or `worker_threads` placement with memory plus explicit snapshot directory
storage. Neither host routes through native `@oliphaunt/ts`.

Use [Rust WASIX](./index) when Rust owns the portable host. Use
[TypeScript](/docs/sdk/typescript) for Node.js, Bun, or Deno applications that
use the native runtime family instead.
