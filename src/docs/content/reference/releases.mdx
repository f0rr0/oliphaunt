Oliphaunt SDKs and runtimes have independent versions. Use the [version table](/docs/reference/version-matrix) to see the package versions documented by this site, and the package's linked release notes for changes.

## Match your dependency

Install examples use the versions associated with this documentation build. Pin dependencies in your package manifest or lockfile so an application rebuild uses the versions you tested.

The SDK package selects compatible runtime dependencies. Keep those dependencies together instead of independently replacing a native library, WebAssembly runtime, or helper executable. React Native also depends on compatible Swift and Kotlin integrations.

Extension packages have their own versions and runtime compatibility. A matching numeric version across unrelated products is not a compatibility guarantee.

## Current integration limitations

The 0.2.0 native Rust quickstart requires the complete runtime archive and explicit environment setup; see [native runtime configuration](/docs/sdk/rust#configure-the-native-runtime). Build-helper registration alone is insufficient in this release.

Native TypeScript 0.2.0 fails fresh-database initialization on Linux x64 under Node.js and Bun with a data-directory permission error. See the [TypeScript quickstart](/docs/sdk/typescript) for the current limitation. The [WASIX TypeScript](/docs/sdk/wasix-typescript) and [WASIX Rust](/docs/sdk/wasix-rust) quickstarts have been verified against their published packages on Linux x64.

## Upgrade an application

1. Read release notes for your SDK, its runtime changes, and selected extensions.
2. Create a recoverable backup and test the upgrade against a copy of application data.
3. Update the application dependency and its lockfile.
4. Rebuild native applications when runtime resources or extensions change.
5. Apply documented schema or extension migrations.
6. Verify queries, transactions, restart recovery, and restore before switching user data.

Use physical restore only when runtime-family and format compatibility are documented. Use logical dump/restore for incompatible formats or transfers between native and WASIX. See [WASIX dump and restore](/docs/sdk/wasix-rust/dump-restore) for an example.

## Documentation versions

This site describes one set of SDK versions at a time, shown in [Versions](/docs/reference/version-matrix). Documentation fixes can update the site without changing a package version.

Each build also provides a [version record](/docs-version.json) containing its source revision and exact product versions. Use it when reporting a discrepancy between the docs and an installed SDK. Release tags retain the source and documentation for that release; this site does not currently host a separate historical site for every package version.

See all [GitHub releases](https://github.com/f0rr0/oliphaunt/releases) for release notes and downloadable artifacts.
