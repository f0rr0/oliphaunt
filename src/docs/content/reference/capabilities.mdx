# Capability Matrix

Choose a product before choosing a feature. Native SDKs embed or supervise the
native runtime, Rust WASIX hosts the portable runtime from Rust, and WASIX
TypeScript hosts it in a browser or Node realm. Sharing PostgreSQL and portable
WASIX carriers does not make those public APIs interchangeable.

Native SDKs expose capability reports for features that can vary by engine or
target. Rust WASIX exposes `engine_capabilities()`. WASIX TypeScript has
a deliberately fixed, smaller surface and does not expose a capability-reporting
method.

## SDKs

| SDK | Package | Primary use | Runtime owner |
| --- | --- | --- | --- |
| C ABI | `liboliphaunt` | Binding authors | Native `liboliphaunt` boundary |
| Rust | `oliphaunt` | Tauri and native Rust apps | Native direct, broker, or server engine |
| Swift | `Oliphaunt` | iOS and macOS apps | Native engine through Swift concurrency |
| Kotlin | `dev.oliphaunt:oliphaunt-android` | Android apps | Native engine through coroutines |
| React Native | `@oliphaunt/react-native` | Expo and New Architecture apps | Swift/Kotlin platform SDKs |
| TypeScript | `@oliphaunt/ts` | Node.js, Bun, and Deno | Native direct, broker, or server engine |
| Rust WASIX | `oliphaunt-wasix` | Rust applications hosting WASIX | Rust-owned WASIX direct or local server API |
| WASIX TypeScript | `@oliphaunt/wasix-ts` | Browser or Node apps choosing portable WASIX | Browser or Node caller realm or Worker |

## Runtime Modes

| Mode | Best for | Session model | SDK availability |
| --- | --- | --- | --- |
| Native direct | Lowest-latency embedded database | One serialized physical session | Rust, Swift, Kotlin, React Native through Swift/Kotlin, TypeScript where its adapter is available, C ABI |
| Native broker | Desktop process isolation or multiple instances | A helper process owns each instance | Rust and TypeScript where supported |
| Native server | PostgreSQL clients, pools, ORMs, and tools | PostgreSQL-compatible server process | Rust and TypeScript where supported |
| Rust WASIX direct | Rust-owned portable embedding | One embedded WASIX backend | `oliphaunt-wasix` |
| Rust WASIX server | Local client-library compatibility | One embedded WASIX backend behind a local endpoint | `oliphaunt-wasix` |
| Browser WASIX | Browser-local SQL | One serialized database in the caller realm or a module Worker | `@oliphaunt/wasix-ts` |
| Node WASIX | Portable SQL without a native runtime | One serialized database in the caller thread or one package Worker | `@oliphaunt/wasix-ts` |

Mobile direct mode has one resident backend per app process and one physical
session. WASIX TypeScript similarly owns one serialized backend per opened
database, placed in the browser or Node caller realm or a Worker. It is not a
native direct mode and does not use the native SDK
contract.

## Choosing A Product

Choose a native SDK when the application ships native `liboliphaunt` or its
native helper processes. Choose Rust WASIX when Rust owns the portable host and
needs the crate's direct, server, archive, or dump APIs. Choose WASIX TypeScript
for the browser or Node direct/Worker API, SQLSTATE recovery, and selective
extension imports; the browser can additionally opt into IndexedDB generations.
Node can opt into directory generations with the same checkpoint and clean-close
snapshot contract.

Do not import native `@oliphaunt/ts` as a fallback for `@oliphaunt/wasix-ts`, and do
not infer a browser API from an API that exists in the Rust WASIX crate.
