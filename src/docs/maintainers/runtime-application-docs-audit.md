# Runtime and application documentation audit

## Scope and design decisions

Reviewed all 42 authored public pages, every heading section within them, both generated public routes, SDK navigation and metadata, Markdown exports, every SDK and example README, and related claims in active maintainer/product documentation. Repository-wide searches included architecture and historical records; those records were not rewritten as current integration instructions.

The correction separates application platform from PostgreSQL runtime. WASIX TypeScript and mobile SDKs appear first in the chooser/sidebar; WASIX Rust explicitly covers native Rust desktop and Tauri apps. General comparisons use native PostgreSQL and WebAssembly PostgreSQL. One short explanation lives at `/docs/sdk#postgresql-as-webassembly`; entry points link to it. Existing page URLs and useful section anchors remain. The runtime guide retains its `/learn/native-runtime` URL and adds scoped WebAssembly sections. The site retains its documentation shell, fonts, dark default, spacing, and Fumadocs components.

Implemented the review proposal: broaden WASIX host/application framing; qualify native Rust/TypeScript labels; promote Swift/Kotlin/React Native; include both Tauri integrations; scope responsiveness, root ownership, client-session and backup claims; distinguish extension source from runtime packaging; correct browser initialization and tools examples; synchronize SDK READMEs, active policies, generated metadata, and text exports.

## Browser initialization finding

The initial review and published WASIX TypeScript 0.2.2 distinguished the root browser host, which exports `runWasix` and can execute `initdb`, from the package-owned browser Worker host, whose host object omitted `runWasix`. That published Worker needs a matching seed or prior initialization. Promise signatures do not establish caller responsiveness.

The 2026-10-10 PR review fetched and rebased onto `origin/main` at `0f5bfcdb42389ce8ad6a8f479203471d827a3865`. That commit exposes `runWasix` in the Worker, enabling seed-free initialization. Final public guidance describes the current optional seed contract and labels the published 0.2.2 limitation separately. The root-initialize/close/Worker-reopen recipes remain compatible with both. Registry reads on 2026-10-10 still reported 0.2.2 as the latest WASIX TypeScript and standard seed versions.

A clean npm install of WASIX TypeScript 0.2.2 loads runtime 0.3.2. The published standard seed 0.2.2 manifest identifies runtime 0.3.0. The browser rejects that combination with `WASIX seed has an incompatible runtime identity`. The final quickstart and logical import recipe use root initialization, close, then Worker reopening. This path executed successfully. The guide explains seed validation and the published mismatch beside the optional seed path; no manifest or validation bypass is suggested. Fixing/publishing seed artifacts is outside this documentation change.
